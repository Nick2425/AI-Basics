# NeuroSoma — Technical Spec

A technical blueprint for NeuroSoma: a Python FastAPI backend serving an interactive Three.js 3D viewport, synchronized Autodesk Inventor-style ViewCube, contextual transparency dimming, floating sticky-note annotations, and a dual-mode knowledge-gap audit engine.

## How This Works, In Plain Language
NeuroSoma pairs a lightweight Python backend with a rich in-browser 3D workspace:
1. **The Brain (Python):** The backend maintains an anatomical knowledge graph (`anatomy_graph.json`) defining the cranial and cervical nervous and musculoskeletal structures. It provides REST endpoints to fetch anatomy data, audit study notes against ground truth concepts, and generate clinical "what-if" challenges.
2. **The View (Browser):** The frontend renders a compact 3-panel workspace. The center panel runs a WebGL 3D scene (Three.js) that visualizes nerves, bones, and muscles generated from the backend data. An interactive Autodesk Inventor-style ViewCube floats in the corner, rotating in 1:1 synchronization with the anatomical camera.
3. **The Audit Loop:** When you ask to audit your notes, the browser sends your notes to the Python audit engine. Python pinpoints the overlooked anatomical concept, identifies its 3D coordinates, and returns a guidance packet. The browser glides the 3D camera to the structure, dims surrounding anatomy to semi-transparency, and opens a clinical "what-if" scenario modal. Once answered, the verified takeaway is saved into your note.

## The Core Journey Through the System
Implements: `prd.md > The Core Journey`
1. **Launch:** The user runs `python app.py` and opens `http://localhost:8000`. The browser initializes the 3-column layout in Surgical Dark mode, queries `GET /api/anatomy`, and builds the 3D scene while loading one sample note in the left tree.
2. **Explore:** The user navigates using the mouse (orbit/pan/zoom) or clicks/drags the 3D ViewCube. Both inputs pass through a shared camera controller. Layer visibility is toggled via the top menu bar (`View > Layers`), which toggles Three.js mesh group visibility.
3. **Inspect & Annotate:** The user clicks a 3D structure (detected via Three.js Raycaster) or types `inspect <name>` in the terminal. The app sets non-selected meshes to `opacity: 0.25` and opens a floating sticky note. If text is entered, it saves to browser `localStorage` and appends to the left tree.
4. **Proactive Prompt:** After note updates, the terminal posts: *"Ready to audit your notes? [Accept] [Decline]"*.
5. **Audit Execution:** On accept, the frontend sends notes to `POST /api/audit`. Python matches concepts against `anatomy_graph.json`, detects an unaddressed structure, and returns its camera target `[x, y, z]` and gap details.
6. **Camera Glide & Isolation:** The frontend smoothly interpolates the 3D camera to the target coordinates, dims surrounding meshes, and highlights audited concepts in the note.
7. **"What-If" Modal:** An overlay prompts the clinical challenge generated by `engine/what_if.py`. The student types an answer, which is validated and appended to the structure's note.

## Stack
- **Backend Language & Framework:** Python 3.10+ with [FastAPI](https://fastapi.tiangolo.com/) (v0.110+) and [Uvicorn](https://www.uvicorn.org/) (v0.28+).  
  *Rationale:* Fast, asynchronous, modern type hints, and built-in static file mounting so the entire app runs from a single process.
- **3D Graphics & Rendering:** [Three.js](https://threejs.org/) (r128 via CDN).  
  *Rationale:* Industry-standard WebGL 3D library providing true 3D camera matrix manipulation, raycasting for anatomical clicks, and material transparency control.
- **Frontend Core:** Vanilla HTML5, CSS3, and JavaScript (ES6 Modules).  
  *Rationale:* Maximum performance and zero frontend build tooling (no node_modules, webpack, or vite required).
- **Icons & Typography:** Google Fonts (Outfit, Inter, JetBrains Mono). Professional clinical CSS iconography without emojis.

## Components

### 1. Backend Server & API Routes (`app.py`)
Implements: `prd.md > Screens and Layout`
- Mounts static files (`/static` to root `/`).
- Endpoints:
  - `GET /api/anatomy`: Returns all anatomical structures, system tags, and 3D coordinate definitions.
  - `POST /api/audit`: Receives `{ notes: [...] }` and returns detected gap, camera coordinates, and explanation.
  - `POST /api/what-if`: Validates student answer to clinical scenario and returns confirmed takeaway.

### 2. Anatomical Knowledge Graph (`data/anatomy_graph.json`)
Implements: `prd.md > 1. Viewport & Anatomical Navigation`
- Ground truth data for the Cranial/Cervical region:
  - Nerves: Vagus Nerve (CN X), Spinal Accessory Nerve (CN XI), Phrenic Nerve, Cervical Plexus.
  - Muscles: Sternocleidomastoid, Trapezius (Superior), Scalene Anterior.
  - Bones: Cervical Vertebrae (C1 Atlas, C2 Axis, C3-C7), Occipital Base.
- Each entry contains scientific name, system category, functional description, clinical correlations, key concepts, and 3D geometric coordinates.

### 3. Dual-Mode Audit Engine (`engine/auditor.py`)
Implements: `prd.md > 3. Proactive Knowledge Gap Audit`
- Local Semantic Concept Matcher: Extracts anatomical keywords and clinical associations from student notes. Evaluates coverage against `anatomy_graph.json`.
- Identifies unaddressed or thin structures and flags the highest-priority gap.
- Supports optional live LLM endpoint if `GEMINI_API_KEY` or `OPENAI_API_KEY` is present.

### 4. Clinical What-If Generator (`engine/what_if.py`)
Implements: `prd.md > 4. "What-If" Clinical Scenario Challenge`
- Generates functional lesion/impairment scenarios for the audited structure (e.g. vocal fold paralysis for Vagus/recurrent laryngeal nerve, scapular winging for Spinal Accessory nerve).
- Validates the student's submission and returns an actionable clinical summary to append to notes.

### 5. 3D Viewport & Synchronized ViewCube (`static/js/viewport.js`)
Implements: `prd.md > 1. Viewport, ViewCube & Transparency Isolation`
- Sets up Three.js WebGLRenderer, PerspectiveCamera, OrbitControls, and Lighting.
- Builds 3D anatomical meshes from `/api/anatomy` data.
- Implements 1:1 synchronized Autodesk ViewCube:
  - Dragging the cube or canvas rotates both in real time without orientation drift.
  - Clicking any face (`FRONT`, `BACK`, `RIGHT`, `LEFT`, `TOP`, `BOTTOM`) triggers smooth camera interpolation.
- Implements Transparency Dimming: sets non-selected meshes to `opacity: 0.25` when a structure is selected or audited.

### 6. Sticky Notes & Tree Controller (`static/js/notes.js`)
Implements: `prd.md > 2. Interactive Sticky-Note Annotations`
- Renders floating sticky-note popups anchored to screen coordinates of selected 3D structures.
- Manages note creation, editing, and deletion. Discards blank drafts.
- Populates the left hierarchical tree with active notes and clinical badges (`[Nerve]`, `[Muscle]`, `[Bone]`).
- Pre-loads 1 sample note on first launch.

### 7. Modern Terminal Console (`static/js/terminal.js`)
Implements: `prd.md > 5. Modern Terminal & Query Console`
- Command parser: `audit`, `inspect <part>`, `layer <nervous|musculo>`, `theme <dark|light|pink>`, `help`.
- Proactive audit prompt handler (*Ready to audit? [Accept] [Decline]*).
- Formats conversational output in clean clinical typography without emojis.

## Data Model

### Anatomy Structure Schema
```json
{
  "id": "vagus_nerve",
  "name": "Cranial Nerve X (Vagus Nerve)",
  "system": "nervous",
  "category": "Cranial Nerve",
  "tag": "[Nerve]",
  "innervation": "Parasympathetic to heart, lungs, digestive tract; motor to larynx/pharynx",
  "clinical_relevance": "Recurrent laryngeal nerve injury causes hoarseness or vocal cord paralysis",
  "key_concepts": ["parasympathetic", "larynx", "pharynx", "recurrent laryngeal", "heart rate"],
  "coordinates": {
    "camera_target": [0.4, 1.2, 1.8],
    "points": [[0.0, 2.2, 0.0], [0.3, 1.4, 0.2], [0.4, 0.6, 0.3], [0.5, -0.4, 0.4]]
  }
}
```

### Audit Response Schema
```json
{
  "status": "gap_detected",
  "target_structure_id": "vagus_nerve",
  "structure_name": "Cranial Nerve X (Vagus Nerve)",
  "camera_target": [0.4, 1.2, 1.8],
  "gap_explanation": "Your notes describe cervical spine posture but omit parasympathetic cranial innervation to thoracic organs via CN X.",
  "audited_terms": ["vagus", "parasympathetic"],
  "what_if_prompt": "What-if the recurrent laryngeal branch of the vagus nerve is damaged during anterior cervical spine surgery? What functional deficit occurs?"
}
```

## Important Failure Modes
1. **Empty Notes on Audit:**
   - *Failure:* User triggers audit without writing any notes.
   - *Fallback:* Terminal replies: *"No notes found to audit. Inspect a structure and jot down some thoughts first."* No camera movement.
2. **100% Comprehensive Notes (No Gaps Found):**
   - *Failure:* User covered all ground truth concepts.
   - *Fallback:* Auditor does not invent false errors; triggers a spaced "what-if" clinical challenge on an older note.
3. **WebGL Unsupported in Browser:**
   - *Failure:* Hardware acceleration disabled.
   - *Fallback:* Viewport displays a graceful fallback canvas with 2D interactive projection and an alert to enable hardware acceleration.

## What Was Simplified and Why
- **Single Segment (Cranial/Cervical) instead of Full Body:** Focusing on the head, neck, and upper cervical spine proves the complete multi-system loop (nerves + muscles + bones) while fitting comfortably inside the 2–4 hour build budget.
- **Parametric Spline/Geometry Models instead of 100MB CAD Meshes:** Generates clean, luminous 3D structures from coordinate arrays in `anatomy_graph.json`. This ensures sub-second load times and guarantees zero missing texture/asset errors during your demo video recording.
- **Local Semantic Concept Graph instead of Mandatory Paid LLM Calls:** Ensures the audit runs instantly and reliably offline with zero API key configuration, while maintaining a clean hook for live AI if desired.

## Decisions and Open Issues
- **Python Backend:** Chosen by the learner to leverage 4 years of Python experience and align with machine learning / AI agent concepts.
- **FastAPI + Three.js:** Selected to provide an asynchronous Python server paired with true WebGL 3D camera matrices and raycasting.
- **Autodesk Inventor ViewCube:** 1:1 synchronized rotation between the cube and the anatomical camera, eliminating orientation drift.
- **Contextual Transparency Dimming:** Dimming surrounding structures to 25% opacity cleanly isolates target anatomy without artificial drawn rings.
- **No Emojis:** Strictly professional clinical typography across all views.
- **One Useful Unknown Resolved:** The 3D coordinate linkage between the Python JSON responses and the Three.js camera tweening was mapped out, ensuring smooth vector transitions during the audit loop.
